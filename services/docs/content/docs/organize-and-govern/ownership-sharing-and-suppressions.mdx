JustScan tracks ownership for scans, registries, suppressions, and status pages. Owners can transfer a resource or grant organization access without making it globally visible.

Suppressions hide accepted findings from the relevant view. Keep each suppression narrow, explain why it is safe, and remove it when a fixed image is available. Use comments and manual findings to preserve team context alongside the scanner output.

On the Suppressions page, use status tabs and CVE search to narrow the rules. **Matching suppressions** counts the current filter scope; accepted-risk, false-positive, and expired counts are labeled **On this page** and describe only the loaded page. Open a rule’s matching images or access menu to inspect its coverage and sharing.

## Xray ignore rules

For Xray scans, JustScan imports active Xray ignore rules as read-only **Xray** suppressions. It lists the rules visible to the registry credential once per scan and applies each rule's scope: vulnerabilities or CVEs, components, artifacts, watches, and policies. Repository-wide and global rules therefore apply as they do in Xray, a rule for another image or tag is skipped, and build or release-bundle rules are not applied to standalone images. A rule limited to a component suppresses only findings for that package, so ignoring a CVE in `openssl` does not hide the same CVE in `libssl3`. Expired rules are skipped.

If the credential cannot list ignore rules, or Xray returns a rule format JustScan cannot evaluate, JustScan falls back to per-vulnerability lookups and then to ignored rows in Xray's violation export. Scan step output records which source was used. See [Xray policy violations](/scan-and-analyze/registries-and-xray) for how ignored violations affect violation context.
