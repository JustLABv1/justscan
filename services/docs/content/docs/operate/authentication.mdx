---
title: Authentication and OIDC
description: Configure local authentication and OpenID Connect for JustScan.
---

JustScan supports local username/password authentication and OIDC. Configure the identity provider from administration, register the backend callback URL, and list the public application URL in `allow_origins`.

The OIDC redirect URI must exactly match the provider registration. The first `allow_origins` value is used as the post-login destination and for notification links.

## Configure OIDC safely

1. Create the provider record in administration and enter the issuer, client credentials, requested scopes, and claim mappings required by your identity provider.
2. Register the backend callback URL shown by the administration flow at the provider. The callback and the public application URL must use the same HTTPS hostname users actually reach.
3. Test normal user sign-in, group-derived organization access, and administrator-role mapping in a non-production or pilot organization.
4. Confirm mapping removals take effect at the next login, then document the offboarding expectation with the identity team.

Group and role claims can grant the JustScan administrator role. Mapping is evaluated at every OIDC login, so removed membership takes effect on the user's next sign-in. Set `local_auth.enabled: false` only after confirming that OIDC sign-in works for administrators.

## Administrator recovery

Keep a tested administrator recovery path while changing OIDC or CORS settings. If local authentication remains enabled, retain a protected local administrator credential. If local authentication is disabled, validate that at least one OIDC administrator can sign in through the public proxy before removing the previous path. A bad redirect URI, wrong `allow_origins` entry, or group claim mapping can otherwise leave the administration area inaccessible.
